# 事件分类地基：time_kind、extras、图片

日期：2026-09-06  
范围：只做首页时间线事件的数据与表单骨架。不做饮食餐次、喝水、运动套路、情绪句式、整天日记整理。

## 背景

首页 `TimelinePanel` 按分类 tab 读写同一张 `event` 表。`EventModal` 对所有分类共用标题、描述、起止时间。后续饮食/喝水/运动/情绪需要不同字段，但不能拆成多张业务表（时间线、统计、AI 日记都依赖 `event`）。

## 目标

1. 每条事件能明确是「时刻」还是「时间段」，统计不以两个时间是否相等来判断。
2. 为分类专用字段预留 `extras` JSON，本期不填业务字段。
3. 事件可附 0～N 张本地图；库中存相对 key，不接 MinIO / 对象存储。
4. `EventModal` 按分类政策渲染时间控件，并留下分类插槽组件（本期为空）。

## 非目标

- MinIO、S3、把图片文件上传到现有网盘。
- 新增情绪、喝水分类。
- 改底部 Tab 导航。
- 云同步传输图片二进制（库里的路径字符串随表现有逻辑走即可）。

## 数据模型

`event` 表增加三列（`initDB` 的 `CREATE TABLE` 与启动时 `ALTER TABLE` 兼容旧库）：

| 列 | 类型 | 含义 |
|----|------|------|
| `time_kind` | TEXT | `instant` 或 `interval`。旧行 `NULL` 视为 `interval`。 |
| `extras` | TEXT | JSON 对象字符串。本期写入 `{}`。 |
| `images` | TEXT | JSON 字符串数组，元素为相对 key，如 `event/img_1710000000_12.jpg`。空为 `[]`。 |

不新增图片表。图片不放进 `extras`。

### time_kind 规则

- 是否为瞬间**只看** `time_kind === 'instant'`（camelCase：`timeKind`）。禁止用 `start === end` 判断。
- 保存 `instant`：只取一个时刻 `T`，`start_datetime` 与 `end_datetime` 写成**同一** `formatDatetime(T)` 字符串（当前格式 `YYYY-MM-DD HH:mm`）。这是给旧查询垫字段，不是判别依据。
- 保存 `interval`：沿用现有起止；校验「开始不得晚于结束」。相等在 interval 下不允许（结束必须晚于开始）；instant 下两端相同，不做「必须晚于」校验。
- 新增时 `interval` 的默认结束时间仍为开始 + 10 分钟。`instant` 不得再 +10 分钟。

### 时长统计

所有按起止差累加时长的路径，排除 `time_kind = 'instant'` 的行；`time_kind IS NULL` 仍计入（旧数据）。至少包括：

- `EventMapper.getTotalStats` 的 `JULIANDAY` 总时长
- `StatisticsMapper` 中按事件时长汇总的 SQL
- `getTotalMinutes` 的调用方：列表展示、`formatEventUtils`、分析输入

辅助约定：可在 `formatTimeUtils` 增加 `getEventDurationMinutes(event)`：`timeKind === 'instant'` 返回 0，否则 `getTotalMinutes(start, end)`。

列表：`instant` 只显示一个时间点（如 `12:30`），不显示「0分钟」。`interval` 仍显示 `12:00–12:40` 与时长。

自动状态（`TimelineList.getFinalStatus`）：`instant` 在当前时间晚于该时刻后视为 `completed`；不要用「进行中窗口」把瞬间当成时段。

## 图片

沿用 `core/db/imageDB.js`：

- `ImageDirType` 增加 `EVENT: 'event'`，目录 `images/event/`。
- `saveImageToLocal` 返回完整本地 URI；写入数据库前改成相对 key：`event/<fileName>`。
- 展示时：`${BASE_IMAGE_DIR}${key}`（注意现有 `BASE_IMAGE_DIR` 已含 `images/`）。
- 选图：已有 `expo-image-picker`，交互对齐储物（相册/相机），事件允许多张。
- 软删事件时删除对应本地文件（对齐 `StorageService.delete`）。更新时删除被用户去掉的旧文件，不删仍引用的文件。

本期不同步图片文件。绝对路径不入库，便于以后接到网盘或对象存储时 key 不变。

## 分类时间政策

配置集中放一处（新建 `constants/eventTimeKindPolicy.js` 或并入 `commonConstans.js`），不要散落在 Modal 里。

| category id | 默认 time_kind | 允许切换 |
|-------------|----------------|----------|
| diet | interval | 是 |
| sports | interval | 是 |
| sleep | interval | 否 |
| work | interval | 否 |
| study | interval | 否 |
| travel | interval | 否 |
| daily | interval | 是 |
| entertainment | interval | 是 |
| shopping | interval | 是 |

- 「全部」tab 新增：以用户选中的分类为准；尚未选分类时按 `daily`。
- 切换分类：若当前是新增草稿且用户没手动改过 time_kind，则套用新分类默认；编辑已有事件时保留已存 `time_kind`。
- 不允许切换：只渲染对应控件（一个时间 或 起止）。允许切换：显示「时刻 | 时间段」。

情绪、喝水本期不建分类。以后：情绪/一口水默认 instant 且不切换；喝完一瓶默认 interval 且可切换。

## UI 结构

`EventModal` 拆出（保持现有主题组件）：

- 公共区：分类、图标、标题、描述、状态、图片。
- 时间区：按政策渲染。
- 分类插槽：`EventCategoryFields`，按 `category` 分发；本期各分类返回 `null`。饮食等业务表单不在本期实现。

`TimelineList`：按 `timeKind` 显示时间；有 `images[0]` 则缩略图。

## 同步与 API

- `eventCreateSchema` / `eventUpdateSchema` / 响应 schema 增加 `timeKind`、`extras`、`images`。
- Mapper `create`/`update` 已按对象键插入，Service 层把 extras/images 序列化为字符串；读出时 `JSON.parse`，失败则 `{}` / `[]`。
- 云同步按表现有整表字段走；新增列会出现在导出 JSON 中。不同步 `images/event/` 目录。

## 错误与边界

- `images` / `extras` 非法 JSON：读作空对象/空数组，不崩溃。
- 图片复制失败：提示失败，不写半条事件；已选但未保存的文件可在取消时不留垃圾（保存成功才 copy 进私有目录，或保存失败时删掉本次 copy）。
- 旧事件打开编辑：`timeKind` 空 → `interval`；无图片 → 空列表。

## 测试要点

- 保存 instant：两条时间字符串相同，`time_kind=instant`，总时长统计不增加。
- 保存 interval：时长与现在一致。
- `NULL` time_kind 的旧行计入时长。
- diet 新增默认 interval，可改为 instant 后再保存。
- sleep 新增无切换控件。
- 多图保存、删事件后本地文件不在。
- 列表 instant 不显示 0 分钟。

## 以后怎么接（不在本期做）

分类字段写入 `extras`（餐次、口数、次数、触发原因等）。喝水容器配置另表或设置项。运动套路为模板 + 一条 session 事件。整天日记仍从当天 event 生成，走现有 `autoGenerateDiaryUtils`。
